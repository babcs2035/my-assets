# UI/UX 点検（2026-10-05）

全画面の UI/UX を点検した記録．読み取りだけで行い，コード・DB・設定は変更していない．
画面での実測（CLS，コントラスト，読み上げ名）と，担当範囲を分けた 4 つのサブエージェントによるコードの読み取りを組み合わせた．
High の指摘と日付の扱いに関わる指摘は，サブエージェントの報告とは別にコードを読んで裏付けた．

## 確度の表記

- **裏付け済み**: サブエージェントの報告とは別に，該当行を読んで確かめた．
- **確認済み**: サブエージェントがコードから確定させた（裏付けはしていない）．
- **要画面確認**: コードだけでは確定できず，画面かデータで確かめる必要がある．

## 先に調べること: 10/02〜10/04 の残高履歴の欠損

次の 3 件は同じ欠損につながっている．

（2026-10-05 追記）点検に使ったローカル DB の欠損は，同期の不具合ではない．スケジューラは `next dev` では起動時のキャッチアップをしない（`src/lib/scheduler.ts:217-223`）ので，08:00 JST にローカルのサーバーが動いていなかった日は履歴ができない．なお，当初ここに書いた `SyncLog` というテーブルは，スキーマにも git の履歴にも存在しない．本番 DB に同じ欠損があるかは確かめていない．3 件はいずれも「欠けた日がある」だけで起きるので，原因の調査を待たずに表示側を直す．

- **DASH-3**（Medium）: 履歴のある日だけを集計し，X 軸がカテゴリ扱いなので日付が詰まる（10/01 の次が 10/05）．一部の口座だけ欠けた日は総額が落ち込む（`src/actions/dashboard.ts:145-160`，`dashboard-charts.tsx:234-241`）．
- **DASH-4**（Medium）: 表示中の口座が 1 つでも前日の履歴を欠くと，「前日比」と表の「前日」列がすべて「—」になる（`src/actions/dashboard.ts:61-75`）．前日の範囲の計算自体は正しい．
- **DASH-11**（Medium，裏付け済み）: 最後の同期が今日でなくても，前回が成功なら灰色の「完了」のまま（`src/components/sync-status.tsx:90-94`）．加えて 08:00〜08:09 は同期の有無を見ずに「実行中...」と出す（`:87-89`）．どちらも時刻だけで状態を推測しているので，`Provider` の `lastSyncAt` と `lastSyncSuccess`（null が同期中．`src/lib/sync-lock.ts`）で判定を一本化する．

## 複数の画面にまたがる問題

同じ原因が画面ごとに別の ID で報告されている．直すときはまとめて扱う．

### 金額の書式

- `formatCurrency(-1234)` は `¥-1,234`，`formatSignedCurrency` は `-¥1,234`，`formatSignedAmount` は `+1,234`（¥ なし）．`formatSignedCurrency` の docstring は「例: ¥-1,234」で実装と合わない（`src/lib/utils.ts:153-176`）．
- 該当: UI-4，ACC-6，DASH-7，AST-1（同じ資産ページで総負債の符号が場所によって逆），TX-15，IE-1（支出の棒をマイナスで描き，ツールチップに `¥-123,456`）．
- 方針案: 負の数を `-¥1,234` に揃え，プラス記号付きと符号付きを 1 つのフォーマッタにまとめる．`Intl` の `currency: "JPY"` は全角の「￥」になるので使わない．

### コントラスト（WCAG AA 4.5:1 未満）

- recharts は軸の `stroke` を目盛りの文字色にも使うので，`stroke="#52525b"` の軸ラベルは約 2.2:1．
- `text-zinc-500` はカード上で約 3.6〜3.8:1，`text-zinc-600` は約 2.2〜2.6:1．
- 該当: DASH-8，ACC-12，SET-14（設定で 22 か所），UI-3（`page-header.tsx:29, 31`，`sidebar.tsx:361`），C-1．
- 方針案: 目盛りは `tick={{ fill: "#a1a1aa" }}`，補助テキストは zinc-400 か `text-muted-foreground`．

### 選んだ期間にデータがないと全期間を黙って表示する

- DASH-9（`dashboard-charts.tsx:88-91`），ACC-7（`account-balance-chart.tsx:95-97`，`holding-trend-chart.tsx:152`）．同期が止まると「1週間」を選んだまま全期間が出る．

### 欠けた日の補完

## 未検証の候補

最初の点検（ファイルをほとんど読めないまま終わった）で挙がり，ほかの担当範囲と重ならないもの．2026-10-05 にコードで確かめた結果を併記する．

- `src/lib/chart-time-range.ts` の「1W」が開始日を含めて 8 日分になる．→ 問題なし．7 日間の変化を描くには 7 日前の点が起点として要り，1M・3M も起点の日を含めていて揃っている．
- `getNiceChartDomain` に `NaN` が混じると範囲が `[NaN, NaN]` になる．→ 事実．有限でない値を除くよう修正（`7858440`）．
- `formatYAxisCurrency` が 99,999,999 付近で「10000万」になる．→ 事実（99,999,500 以上 1 億未満．9,999.5 も「¥10,000」）．丸めた後の値で単位を決めるよう修正（`0dcb1e2`）．
- `global-error.tsx` がないので，root layout 内の例外を受けられない．→ 事実．root layout 自体が落ちたときだけ Next.js 既定の英語画面になる．日本語の `global-error.tsx` を追加（`b98b815`）．
- `viewportFit: "cover"` と `black-translucent` で，iOS の sticky ヘッダーがステータスバーに重なりうる．→ `env(safe-area-inset-*)` がどこにもなく，重なる条件は揃っている．ヘッダー・メニュー・本文・トーストに safe-area の余白を確保（`9cfdf90`）．実機では未確認．
- `error.tsx` から `src/lib/logger.ts` を import していて，ブラウザで動くか確かめていない．→ 問題なし．pino 10.3.1 の `browser` フィールドにより，クライアントでは console に出す `browser.js` が使われる．

## 確認して問題がなかった点

- JST の扱い: 残高履歴の JST 08:00 保存，KPI の前日の範囲，`formatJSTDate` による日付キー，請求日と取引日の「JST 日付の UTC 0 時」での境界は整合している．
- 古い応答の破棄（`requestIdRef`，`cancelled` フラグ），削除とインポートの `$transaction`，並べ替え失敗時の巻き戻しはできている．
- `error.tsx` と `not-found.tsx` は日本語で，例外の詳細を出さない．スキップリンク，`lang="ja"`，フォーカス枠がある．

## 直す順番の案

1. 10/02〜10/04 の欠損の原因を調べる（DASH-3，DASH-4，DASH-11 の前提）．→ ローカルで 08:00 にサーバーが動いていなかったためと判明（上の「先に調べること」を参照）．
2. データを壊すもの: SET-1，TX-1，TX-2（TX-3 の取り消し手段と合わせて検討），SET-5．
3. 誤った数字を出すもの: DASH-1，ACC-1，ACC-2，ACC-3，DASH-12，TX-4，TX-5，TX-6．
4. 横断的な問題を 1 項目 1 commit で: 金額の書式，コントラスト，期間のフォールバック，欠けた日の補完．
5. 404 と Suspense，初回取得のレイアウトのずれ（SET-2）．影響が全ルートに及ぶので，`pnpm build` のルート一覧と画面で確かめる．
6. 残りの Medium と Low．

日付の境界を変えるもの（DASH-1，DASH-6，DASH-12）は，`src/lib/utils.test.ts` に月末・うるう年・JST 09:00 前後のケースを足してから直す．
